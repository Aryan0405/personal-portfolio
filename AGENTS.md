
# Portfolio Development Guidelines

## Project Context
This is a personal portfolio for a Data Science undergraduate and aspiring Data Scientist.

The website showcases projects, technical skills, experience and professional growth.

The goal is to create a distinctive, premium-quality portfolio that demonstrates technical competence and strong visual taste.

## Design Direction

- Aim for premium, modern, editorial-quality design.
- Prioritize strong typography, whitespace, composition and visual hierarchy.
- Avoid generic AI-generated website aesthetics.
- Avoid unnecessary gradients, glassmorphism, excessive rounded cards and repetitive layouts.
- Use a consistent design system across all sections.
- Every design decision should have a clear purpose.
- Make the website memorable without sacrificing usability.

## Design Skills

When available, use the installed skills appropriately:

- UI UX Pro Max: design systems, typography, colour palettes and UX.
- Taste: visual direction, composition and frontend aesthetics.
- Impeccable: critique, refinement, accessibility and visual polish.
- Brag: project showcase and launch-video creation when relevant.

Do not blindly follow skill suggestions. Apply design judgement.

## Portfolio Design Priorities

1. Hero: distinctive introduction, strong typography and clear positioning.
2. About: concise professional identity and relevant background.
3. Projects: showcase real technical work, problem-solving, methodology and results.
4. Skills: organized, credible and easy to scan.
5. Contact: clear calls to action and professional links.

Give projects enough visual space to communicate their technical depth.

## Motion and Interaction

- Use purposeful transitions and micro-interactions.
- Use scroll-based animations only when they improve storytelling.
- Keep animations smooth and performant.
- Respect reduced-motion accessibility preferences.
- Avoid distracting or excessive animations.

## Technical Standards

- Inspect the existing architecture before making changes.
- Preserve the existing Astro architecture and conventions.
- Reuse components where appropriate.
- Keep code maintainable and avoid unnecessary dependencies.
- Ensure responsive layouts across desktop, tablet and mobile.
- Maintain accessibility, semantic HTML and good performance.
- Do not remove existing functionality without justification.

## Development Workflow

For significant design changes:

1. Inspect the existing implementation.
2. Critique the current design.
3. Establish the intended visual direction.
4. Identify the highest-impact improvements.
5. Implement changes incrementally.
6. Inspect desktop and mobile layouts.
7. Fix visual inconsistencies.
8. Run the production build and resolve errors.

Do not redesign everything blindly.

Preserve strong existing design decisions and improve weak ones.

## Project Integrity

- Never invent project achievements, metrics or experience.
- Keep project descriptions factually accurate.
- Do not fabricate testimonials or credentials.
- Preserve working links and existing integrations.
- Ask before making major architectural changes.

## Quality Bar

The finished website should feel intentionally designed by a skilled designer and implemented by an experienced frontend engineer.

Prioritize visual quality, clarity, credibility, performance and usability over unnecessary complexity.
